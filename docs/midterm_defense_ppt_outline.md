# 中期答辩 PPT 大纲

## 整体要求

- 主题：面向药物相互作用识别的知识图谱增强大模型可解释推理研究
- 结构：绪论背景、研究思路、关键研究部分（目前的实验进展）、存在的困难和目前的解决方案、预期成果
- 页数：约 20 页
- 风格：科学、专业、简洁，关键内容使用流程图、表格和插图辅助表达
- 维护方式：逐页确认后纳入正式大纲

### 内容设计约束

- “绪论背景”拆分为多个分页：国内外研究现状、现有方法不足、本项目任务定义。
- 单页原则上只保留一项核心图或表，避免图表与正文争夺版面。
- 绪论背景最终安排为两页：第 3 页介绍国内外研究现状；第 4 页合并现有不足与本项目任务目标，并过渡到“研究思路”。
- 模型输出采用两条相互独立的任务轨道，不在同一次微调中混合：
  1. DDI 类型分类；
  2. 机制推理过程与结构化解释生成。
- 两条任务轨道使用不同的微调数据和提示模式，并分别评估。
- 机制解释采用双模驱动：外部模型可直接通过 API 输出推理链，也可作为教师生成蒸馏数据，由本地 Llama3 LoRA 承担低成本批量推理。
- 在外部模型直接生成推理链、蒸馏微调和常规推理之外，后续加入 Agent Loop 工程化环节：生成结果经过事实度与机制质量评价，不达标时将评价反馈注入上下文并重新生成。
- PPT 中区分“实测结果”和“Mock 预期水位”：Mock 用于实验前对齐效果、提出机制假设和设置验收区间，正式答辩时再由可追溯实验结果替换或并列验证。

## 第 3 页：国内外研究现状

### 所属章节

1. 绪论背景

### 页面标题

药物相互作用识别研究现状

### 核心观点

DDI 研究已由规则和传统机器学习分类，逐步发展到领域预训练模型、知识图谱增强和大模型推理；但面向机制解释的证据约束与可靠性评价仍不充分。

### 核心表格

`【表 3-1：国内外 DDI 自动识别研究现状对比表】`

| 研究阶段 | 国外研究进展 | 国内研究进展 | 主要特点 |
|---|---|---|---|
| 规则与传统机器学习 | 基于词典、句法特征和 SVM 等进行药物实体与关系识别 | 开展中文医学文本实体识别、关系抽取及规则系统研究 | 可解释，但依赖人工特征，泛化能力有限 |
| 深度学习与预训练模型 | CNN、LSTM、BioBERT 等用于生物医学关系抽取 | 采用 BERT 和医学预训练模型处理中文医疗文本 | 分类性能提高，但通常只输出标签 |
| 知识图谱增强 | DrugBank、PrimeKG 等用于补充药物、靶点和通路关系 | 医学知识图谱逐步用于辅助诊疗和药物关系分析 | 提供外部知识，但存在噪声和实体对齐问题 |
| 大语言模型与智能体 | 探索提示学习、检索增强、医学推理及评价反馈 | 医疗大模型和知识增强应用快速发展 | 能生成解释，但存在幻觉、方向错误和评价困难 |

### 代表性研究依据

- DDIExtraction 2013 建立了标准化 DDI 文本抽取任务，为后续关系分类研究提供统一基准。
- BioBERT 等领域预训练模型显著提升了生物医学关系抽取能力，但核心范式仍以分类为主。
- PrimeKG 整合多源生物医学实体与关系，为 DDI 机制知识增强提供了数据基础。

- `【参考文献：SemEval-2013 Task 9 / DDIExtraction 2013】`
- `【参考文献：BioBERT】`
- `【参考文献：PrimeKG】`

### 本页结论

国内外研究正在从“识别相互作用类别”向“生成可信机制解释”演进，知识证据利用和解释可靠性控制成为新的研究重点。

## 第 4 页：现有不足与本项目任务目标

### 所属章节

1. 绪论背景

### 页面标题

从“关系分类”走向“可信机制推理”

### 核心观点

现有方法在分类性能、机制解释、知识利用和生成可靠性之间仍存在断层。本项目不将所有能力压入同一个输出，而是采用分类与解释解耦、知识增强、内外双模驱动和评价反馈修正的研究路径。

### 页面布局

采用左右双栏布局。左栏为 4 张浅灰色“现有不足”卡片，右栏为 4 张蓝绿色“研究目标”卡片，中间用细箭头建立对应关系。页面下方放置一句任务定义，不再增加第二张图表。

### 卡片内容

| 现有不足 | 对应研究目标 |
|---|---|
| 模型通常只给出标签；分类与解释混合学习时目标容易干扰 | 将分类与解释拆为独立轨道，分别使用微调数据、提示模式和评价体系 |
| 原始 KG 关系冗余，直接输入可能放大噪声 | 提取与句子语义相关的酶、转运体、靶点等机制证据 |

## 第 5 页：总体研究思路

### 所属章节

2. 研究思路

### 页面标题

总体技术路线：任务双轨与模型双模协同

### 核心流程图

`【图 5-1：DDI 任务双轨、模型双模与评价反馈总体技术路线图】`

建议采用从左到右的主流程。先拆分分类与解释任务，再将解释任务分为“外部模型直接驱动”和“本地蒸馏模型驱动”两条路径，最终进入统一评价与 Agent Loop：

```text
DDI 文本 + 药物对 + 可选 PrimeKG
                 ↓
        数据清洗与机制证据构建
                 ↓
      ┌──────────┴──────────┐
      │                     │
  分类任务轨道          机制解释任务轨道
 标签数据 + LoRA              ↓
   五分类输出       ┌─────────┴─────────┐
      │             │                   │
 分类指标评估    外部模型直接驱动      本地蒸馏模型驱动
                API 直接生成推理链     外部模型生成训练 output
                无训练、低维护         Llama3 QLoRA 微调
                高成本、较高时延       本地推理、低边际成本
                     │                   │
                     └─────────┬─────────┘
                               ↓
                 Faithfulness + Mechanism Judge
                               ↓
                 Agent Loop 评价反馈与迭代修正
```

### 流程旁专业说明

- **任务解耦**：分类与解释分别训练，减少标签预测与长文本生成之间的目标冲突。
- **知识增强**：PrimeKG 只提供机制锚点，不直接替代文本证据和模型推理。
- **双模驱动**：外部模型直接推理强调易接入和低维护，本地蒸馏模型强调低边际成本、低时延和数据可控。
- **能力迁移**：利用外部模型生成训练推理链，再通过 LoRA 将机制解释能力迁移至本地模型。
- **闭环控制**：以确定性事实度与机制质量评价共同驱动输出修正。

### 设计提示

本页流程图是整场答辩的核心总图。使用蓝色和青绿色区分分类/解释任务，用实线与虚线区分外部直推/本地蒸馏路径；Agent Loop 使用低饱和橙色强调。外部直推不是蒸馏流程的一部分，而是与本地蒸馏模型并列的运行方案。

## 第 6 页：双轨任务与数据设计

### 所属章节

2. 研究思路

### 页面标题

分类与解释解耦的任务建模

### 核心版式

采用上下两条横向任务带，每条任务带包含“输入—微调数据—模型输出—评价指标”四个模块。两条任务带共用左侧输入，但中后段完全分离。

### 任务轨道 A：DDI 类型分类

- 输入：`sentence + query_group + 可选 kg_evidence`
- 微调数据：`label_only_with_kg / label_only_without_kg`
- 输出：`Mechanism / Effect / Advice / Int / False`
- 评价：Accuracy、Macro-F1、Weighted-F1、各类别 Precision/Recall/F1

### 任务轨道 B：机制解释生成

- 输入：`sentence + query_group + 可选 kg_evidence`
- 模型路径 B1：外部模型直接生成，不依赖本地微调数据
- 模型路径 B2：使用 `reasoning_without_kg / reasoning_with_kg` 蒸馏数据微调本地 Llama3
- 输出：`analysis_steps + mechanism_summary + representative_pairs`
- 评价：证据覆盖率、幻觉率、查询覆盖率、机制链完整性、方向正确性和机制粒度

### 结构示例

`【图 6-1：DDI 分类轨道与机制解释轨道的数据—输出契约图】`

图中明确标注：两条轨道使用不同训练文件、不同 prompt mode 和不同评价协议；解释轨道不强制输出标签，分类结果可作为独立 sidecar 使用。

### 本页结论

任务解耦保证分类能力可独立优化，也使机制解释能够专注于证据组织和推理链质量。

## 第 7 页：知识增强与数据构建策略

### 所属章节

2. 研究思路

### 页面标题

从原始知识图谱到句子条件下的机制证据

### 核心流程图

`【图 7-1：PrimeKG 机制证据筛选与微调样本构建流程图】`

```text
DDI 原始文本与标注
        ↓ 药物实体解析与名称对齐
目标药物对 / query_group
        ↓ PrimeKG 一阶邻域查询
候选酶、转运体、靶点、通路关系
        ↓ 可靠关系过滤 + 句子 cue 匹配 + 去除低价值 PPI
机制证据摘要 kg_evidence
        ↓
分类输入数据 / 解释蒸馏输入数据
```

### 关键策略说明

- 将逐药物对枚举压缩为 `query_group`，减少重复 token 和长列表噪声。
- 根据 `metabolism、renal、clearance、QT、receptor` 等句子线索选择机制槽位。
- 优先保留 `CYP、UGT、SLC22、SLC47、SLCO、ABC、KCN、SCN` 等可靠机制锚点。
- 对缺少可靠证据的样本显式标记证据不足，不强行构造共同节点。

### 本页结论

知识图谱在本研究中承担“机制锚点”而非“答案生成器”的角色。

## 第 8 页：双通道评价的必要性

### 所属章节

2. 研究思路

### 页面标题

为什么必须双通道评价：三个候选解释的对照

### 页面形式

`【图 8-1：三个候选解释在 Faithfulness 与 Judge 下的对照卡片】`

### 三类候选解释

- **候选 A：保守复述。** 内容紧贴原句，因此 Faithfulness 较高；但只重复相互作用结论，没有给出机制链，Judge 得分偏低。
- **候选 B：丰富但脱离证据。** 解释结构完整、术语丰富，Judge 可能给出较高质量分；但多个机制或处置建议无法由原句和 KG 支持，Faithfulness 不通过。
- **候选 C：证据约束机制链。** 仅围绕可验证证据组织“作用对象—变化方向—机制结果”，同时通过事实约束与机制质量评价。

### 方法动机

Faithfulness 守住事实底线，Judge 排除“正确但没有解释价值”的低信息答案；二者组合后，才能为后续增量微调筛出既可靠又有教学价值的机制推理数据。

## 第 10 页：数据表示与解释输出优化

### 所属章节

3. 关键研究部分（目前的实验进展）

### 页面标题

面向群组 DDI 的紧凑输入与结构化输出

### 核心版式

采用“优化前—优化后”左右对比卡片。每张卡片展示一段短 JSON 和 2 条说明，避免使用完整代码截图。

### 优化前

```json
{
  "sentence": "...",
  "queries": "1. A -> B\n2. A -> C\n3. A -> D",
  "kg_evidence": "大量一阶邻域节点与关系"
}
```

- 同一施动药重复出现，prompt 冗长。
- 模型容易逐 pair 机械扩写并引入句外机制。

### 优化后

```json
{
  "sentence": "...",
  "query_group": "- A -> {B, C, D}",
  "kg_evidence": "筛选后的机制锚点摘要"
}
```

解释输出统一为：

```json
{
  "query": "GLOBAL_PHENOMENON",
  "analysis_steps": "2-4 个短步骤",
  "mechanism_summary": "机制摘要",
  "representative_pairs": ["最多 3 对"]
}
```

### 阶段价值

减少输入重复和输出枚举噪声，使解释评价从字符串匹配转向结构化 claim 分析。

## 第 11 页：分类轨道实验进展

### 所属章节

3. 关键研究部分（目前的实验进展）

### 页面标题

五分类基线结果：原始 KG 输入尚未带来稳定增益

### 核心表格

`【表 11-1：Llama3 LoRA 五分类 With-KG/No-KG 阶段性结果】`

| 模型设置 | 样本数 | Accuracy | Macro-F1 | Weighted-F1 |
|---|---:|---:|---:|---:|
| Label-only With-KG | 1026 | 88.99% | 76.89% | 88.92% |
| Label-only No-KG | 1042 | **91.55%** | **80.35%** | **91.42%** |

表下注明：该结果来自早期历史实验，两组有效样本数不同，主要用于阶段性诊断，最终实验将基于统一样本集合重跑。

### 结果解读

- No-KG 基线当前优于直接输入原始 KG 的设置，说明知识量增加不等于有效信息增加。
- `Int` 类样本较少且 F1 较低，是当前分类轨道的主要薄弱类别。
- 结果促使研究重点由“拼接更多 KG 节点”转向“筛选句子条件下的机制证据”。

### 页面强调语

> 阶段性结论：需要优化的是 KG 证据质量与使用方式，而非简单扩大图上下文。

## 第 13 页：解释质量评价框架

### 所属章节

3. 关键研究部分（目前的实验进展）

### 页面标题

“事实约束 + 机制深度”的双通道评价

### 核心版式

页面中央放一条解释输出，向下分叉到两个并列评价面板，底部汇合为综合诊断。两个面板采用不同色系，避免再放评价指标表。

### 左侧：确定性 Faithfulness

- 解析结构化输出并抽取机制 claims。
- 以原句和可选 KG evidence 为证据集合。
- 区分 supported、partially supported、unsupported。
- `Strict Coverage = supported claims / 全部 claims`。
- `Hallucination = unsupported claims / 全部 claims`。
- `Query Coverage = 输出覆盖的目标药物对 / 输入目标药物对`。
- `Consistency` 根据解释文本与对应 DDI 类型关键词的一致程度计算，并对显式矛盾表达扣分。
- With-KG 实验额外计算 `KG Grounded Ratio = 获得 KG 证据支持的 claims / 全部 claims`。

### 右侧：LLM-as-Judge

- 模型：Qwen-Max。
- 重点评价机制链完整性、方向正确性、机制粒度、内部一致性、不确定性校准和临床可用性。
- 采用 0–2 分维度 rubric，总分 0–12，并输出机制缺口。

### 核心图示

`【图 13-1：解释输出的 Faithfulness 与机制 Judge 双通道评价框架】`

### 方法定位

Faithfulness 守住证据底线，Judge 衡量机制解释是否完整、明确和有用；二者并列，不互相替代。

3. 关键研究部分（目前的实验进展）

### 页面标题

双模实测基线与 With-KG 预期效果对齐

### 核心表格

`【表 14-1：Llama3 Base、蒸馏 LoRA、外部模型 Direct 实测结果及 With-KG Mock 水位】`

| 指标 | Llama3 Base No-KG | 蒸馏 LoRA No-KG | 蒸馏 LoRA With-KG（Mock）† | Qwen-Plus Direct No-KG |
|---|---:|---:|---:|---:|

| Query Coverage | 20.74% | 74.29% | 80.0%† | 72.52% |

| Hallucination（越低越好） | **5.25%** | 37.29% | 22.0%† | 45.38% |
| Consistency | 58.12% | 23.29% | 68.0%† | 61.58% |
| Judge Overall | 待统一全量重评 | 待统一全量重评 | 9.2 / 12† | **8.49 / 12** |

`†` 表示基于现有 No-KG/Direct 基线与知识增强机制假设设定的 **Mock 预期水位**，用于实验前效果对齐和异常诊断，不是已观测实验结果。

### 指标计算口径

建议在表格下方使用 5 个横向短标签，每个指标只保留一行说明：

- **Query Coverage**：输出 `representative_pairs` 命中的目标药物对数 ÷ 输入目标药物对总数。
- **Strict Coverage**：由原句及可选 KG 证据严格支持的机制 claim 数 ÷ 输出机制 claim 总数。
- **Hallucination**：无法由原句及可选 KG 证据支持的机制 claim 数 ÷ 输出机制 claim 总数，越低越好。
- **Consistency**：解释中与预测 DDI 类型一致的关键词命中程度，经标准化并扣除显式矛盾后得到 0–1 分数。
- **Judge Overall**：Qwen-Max 按机制链完整性、方向正确性、粒度、内部一致性、不确定性校准和临床可用性六个维度分别评 0–2 分，合计 0–12 分。

### 结果口径说明

- Base、LoRA No-KG 和 Qwen Direct 的 Faithfulness 均来自 1042 条测试集；Qwen Direct Judge 也已完成 1042 条全量评价。
- Base 与 LoRA 当前缺少冻结版 Judge 的全量结果，因此表中保持“待统一全量重评”。
- With-KG Mock 水位的设定逻辑是：在维持 query coverage 的同时，提高证据支持和一致性，并将 hallucination 显著压低；实际结果用于验证或修正该假设。

### 页面结论

> 已有结果说明本地蒸馏和外部直推都能显著提升目标关系覆盖，但均存在证据外推；With-KG 的核心验收标准是同时改善严格支持率与幻觉率，而不是只提高 Judge 总分。

## 第 15 页：双模驱动的工程取舍

### 所属章节

3. 关键研究部分（目前的实验进展）

### 页面标题

外部模型与本地微调模型的互补定位

### 核心版式

采用左右双栏方案卡片，中间放置“按场景选择”的决策箭头。左侧外部模型，右侧本地微调模型；页面底部放一条混合使用策略，不再重复第 14 页指标表。

### 左侧卡片：外部模型直接驱动

- **优点**：无需训练；接口接入快；模型能力随服务升级；无需定期维护本地权重和推理环境。
- **局限**：按调用计费；网络往返导致时延；受 API 限流和可用性影响；存在数据出域与版本不可控问题。
- **适用场景**：低频、高价值、快速原型、教师数据生成和复杂样本兜底。
- **当前进度**：Qwen-Plus 已完成 1042 条 single-pass 全量直评，生成成功率 100%。

### 右侧卡片：本地蒸馏模型驱动

- **优点**：部署后边际成本低；批量推理速度稳定；数据留在本地；模型版本可冻结和复现。
- **局限**：需要构建蒸馏数据、训练 LoRA、维护模型和 GPU 环境；能力受基座容量与蒸馏质量限制。
- **适用场景**：高频批量任务、隐私敏感数据、固定业务流程和离线环境。
- **当前进度**：Llama3 No-KG LoRA 已完成全量推理评价；With-KG 精炼实验待验证。

### 底部混合策略

```text
常规批量样本 → 本地 LoRA
高难度 / 低置信度样本 → 外部模型
两类输出 → 统一评价协议与 Agent Loop
外部高质量结果 → 反哺下一轮本地蒸馏训练
```

### 本页结论

双模驱动不是两套孤立系统，而是以本地模型承担规模化推理、外部模型承担教师与兜底，并通过统一评价和持续蒸馏形成协同。

## 第 16 页：Agent Loop 工程化设计

### 所属章节

3. 关键研究部分（目前的实验进展）

### 页面标题

从单次生成扩展为评价反馈驱动的迭代推理

### 核心循环图

`【图 16-1：DDI 机制解释 Agent Loop 生成—评价—反馈—重试闭环】`

```text
初始 Prompt
    ↓
Reasoner 生成解释
    ↓
Faithfulness Critic ── 可选 Judge Critic
    ↓
是否达到阈值？ ── 是 → 输出最佳结果
    │
    否
    ↓
提取 unsupported claims / mechanism gaps
    ↓
反馈注入 messages → 下一轮生成（最多 N 轮）
```

### 当前实现

- 生成器与 Critic 解耦，可接外部模型或本地 LoRA。
- 每轮记录 output、critic 分数、失败原因、反馈内容和终止原因。
- 支持事实度阈值、Judge 阈值、最大轮数和轨迹落盘配置。
- 外部直评入口和本地推理入口均已预留集成点。

### 后续实验占位

`【实验 16-A：Single Pass 与 Agent Loop 的质量增益—调用成本对比】`

核心指标：通过率、平均轮数、幻觉率变化、Judge 增益、token/API 成本和失败类型分布。

## 第 17 页：困难一——知识图谱证据质量

### 所属章节

4. 存在的困难和目前的解决方案

### 页面标题

PrimeKG 覆盖丰富，但并非所有邻域关系都能解释当前 DDI

### 核心版式

采用中央“问题样本”卡片，周围连接三组“问题—原因—方案”短卡片。背景保持留白，不使用复杂网络图。

### 问题与方案

1. **低价值邻域噪声**
   - 问题：一阶邻域可能以 PPI 或泛化 Gene/Protein 关系为主。
   - 方案：建立可靠关系白名单，优先酶、转运体、靶点和离子通道。

2. **关系方向与语义不足**
   - 问题：图中有关联不等于可判断底物、抑制剂或作用方向。
   - 方案：KG 仅提供机制锚点，结论方向必须由句子 cue 支持；无法确定时采用保守表达。

3. **药物名称与图实体不对齐**
   - 问题：商品名、通用名和复合药物导致节点匹配失败。
   - 方案：维护药名映射、记录 unmatched pairs，并对无可靠证据样本显式降级为 sentence-only。

### 当前解决进展

- 已完成 `query_group` 压缩和旧字段兼容。
- 已形成 sentence-conditioned 机制槽位与 anchor family 设计。
- With-KG 新版证据摘要规则仍在迭代，尚未形成最终全量实验结果。

### 页面结论

知识增强的关键不是“查到关系”，而是“判断该关系是否足以支持当前句子的机制结论”。

## 第 12–20 页 Agent Loop 主线修订版（当前制作基准）

### 第 12 页：同一病例下的双模输出差异

- 采用华法林—氟康唑案例，在相同输入证据下并排展示外部 Direct 与本地蒸馏 LoRA 的典型输出模式。
- 外部模型展示更完整的 CYP2C9—S-warfarin 清除—暴露/抗凝效应—出血风险长链，同时标出其可能扩写当前证据未提供的处置建议。
- 本地模型展示更短、更稳定的机制链，强调批量推理优势及复杂机制粒度不足。
- 本页结论：外部模型用于复杂失败诊断与高质量重推，本地模型用于常规批量推理。

### 第 13 页：可解释评价体系的具体实现

- **统一输入**：读取 `sentence`、`reasoning`、`query_group` 与可选 `kg_evidence`，保证两条评价通道使用同一样本。
- **结构归一化**：`processor.py` 优先解析 JSON；解析失败时回退为纯文本切分，并抽取 `core_claims`、`optional_inference`、`mechanism_summary`、`analysis_steps` 与代表性药物对。
- **Faithfulness 通道**：`faithfulness.py` 将解释拆为 claim，以原句或“原句 + KG”为证据集，通过规范化 token、`support_score`、`token_precision` 和 unsupported token 判定 `supported / partial / unsupported`，汇总 coverage、hallucination、query coverage、consistency 与 KG grounded。
- **Judge 通道**：`qwen_judge.py` 在 `temperature=0`、JSON 输出约束下，对方向正确性、机制完整性、证据一致性、粒度、内部一致性与临床可用性六个维度分别给出 0–2 分。
- **结果归一化**：`result_normalizer.py` 裁剪并汇总六维得分，生成 overall、good/fair/poor 决策、gaps 与 rationale。
- **结果落盘**：`workflows.py` 分别保存 Faithfulness 和 Judge 的 detail/summary 文件，便于样本级复核、模型间对照与 Agent Loop 质量门控复用。
- **实现原则**：Faithfulness 不读取 Judge 结论，Judge 也不读取 Faithfulness 标签，避免同源偏差；最终准入阶段再组合两条结果。

### 第 14 页：双模结果与通俗指标口径

- 保留 Base No-KG、LoRA No-KG、LoRA With-KG Mock、Qwen Direct 的全量对比表。
- Query Coverage：目标药物对是否真的出现在解释中。
- Strict Coverage：写出的机制中有多少能被原句或 KG 直接支持。
- Hallucination：写出的机制中有多少找不到证据，越低越好。
- Consistency：机制方向是否与 DDI 类型一致，并扣除前后矛盾。
- Judge Overall：六个机制质量维度各 0–2 分，总分 0–12；不代表事实真实性。
- LoRA With-KG 继续明确标记为 Mock 完成水位，不作为已观测结果。

### 第 15 页：为什么需要 Agent Loop

- 批量数据默认由本地蒸馏 LoRA 处理，通过评价的样本直接进入结果集。
- 只有重复失败或方向性错误样本进入长尾队列。
- 案例展示同一本地模型两次生成均保留“酶抑制导致清除增加”的方向错误。
- 研究判断：相同模型重采样可能复制参数偏差，需要引入不同能力来源进行诊断。

### 第 16 页：在线修复—离线学习闭环

- 本地批量推理经过双通道评价，通过样本直接写入结果。
- 失败样本携带原句、筛选 KG、本地失败链和 claim 级报告进入外部诊断。
- 外部重推结果由同一评价门再次验收，合格纠正链进入增量数据池。
- 数据完成去重、来源、版本和回放集治理后，周期性更新 LoRA。
- 本地模型 v(t+1) 回到下一周期主干，目标是降低同类错误和外部调用率。

### 第 17 页：单样本如何转化为增量训练记录

- 第一步保留本地失败链。
- 第二步由评价器标出 supported claim、方向矛盾和缺失环节。
- 第三步由外部模型解释错误原因并给出纠正链。
- 第四步保存 instruction、evidence_summary、bad_chain、critique、target_chain、scores、provenance 和 model_version。
- 独到之处：不仅保存正确答案，还保存“错误链—诊断—纠正链”的学习轨迹。

### 第 18 页：外部候选的质量门控

- 硬门槛：结构合法、药物对匹配、claim 有据、类型方向一致、无显式矛盾。
- 软排序：Judge 机制质量、简洁性、与已有数据的互补性。
- 数据治理：去重、泄漏检查、来源与版本追踪、困难样本和历史回放配比。
- 丰富但无依据的候选直接拒绝；事实安全但浅层的候选带反馈重推；双门控通过的候选进入增量池。
- 评价体系拥有最终数据准入权，避免把外部模型幻觉蒸馏进本地模型。

### 第 19 页：Agent Loop 对照实验

| 实验组 | 设置 | 回答的问题 |
|---|---|---|
| A Local Single Pass | 本地单次输出，无重试、无外部调用 | 原始批量基线 |
| B Local Self-Retry | 同一本地模型带反馈重试 | 重采样本身是否有效 |
| C External Correction | 外部诊断与纠正，不更新本地模型 | 外部教师的即时修复上限 |
| D Full Agent Loop | 外部纠正、增量数据、周期性 LoRA | 纠错能否沉淀为本地能力 |

- 即时质量：门控通过率、Hallucination、Strict Coverage、Judge 增益。
- 闭环效率：外部调用率、平均轮数、单位合格样本 Token/API 成本。
- 跨周期学习：同类错误复发率、本地通过率、历史回放集退化。
- 状态：Agent Loop 为唯一未完成实验，不预填实验结果。

### 第 20 页：预期成果

- 方法：失败驱动 Agent Loop、事实—机制双门控、在线修复—离线学习分层。
- 数据：失败链—诊断—纠正链三元组及 claim 级证据、评分、来源和成本。
- 模型：版本化本地 LoRA、长尾错误定向学习、历史回放约束遗忘。
- 系统：本地模型承担规模，外部模型解决长尾，质量—成本—数据收益可度量。
- 核心贡献：让每一次高成本外部调用不只修复一个样本，还提高下一版本本地模型解决同类问题的能力。

## 全局视觉与制作规范

### 视觉风格

- 主色：深蓝；辅助色：青绿；强调色：低饱和橙；背景：白或极浅灰。

- 每页保留 1 个核心结论，正文建议不超过 6 个短要点。
- 一页可使用流程图、表格、卡片、对比布局或时间线中的一种主要形式。
